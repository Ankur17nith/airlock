┤ The trap ├

The help exists. The price is your record.

Reading codes, knowing the rules and writing the letter is exactly what language models are good at. But asking one today means pasting your NAME BIRTHDAY INSURANCE ID DIAGNOSIS into a chatbot.

And the obvious hybrid design has a trap of its own: PREFER_ON_DEVICE quietly sends the request to the cloud whenever the device has no model.

03
┤ The idea ├

The model that knows your name
never meets the model that knows billing.

04
┤ Read + seal · on device ├

Each identifier becomes a token.

  • The image never leaves. Nano reads it into JSON under a schema.
  • Identity goes into a vault: AES-GCM in IndexedDB, 24 hours.
  • Dates become day offsets. Codes and amounts stay exact.
05
┤ The guard ├

Code, not a prompt.

Before any byte leaves, the exact request is scanned for every sealed value written any way: upper case, reordered, digits only, last six digits, fourteen date formats. One hit and the request is refused.

"description": "Therapeutic injection, IM
                ref 884120937"
→ BLOCKED · MEMBER_ID (digits) · 88•••••37
06
┤ Audit · in the cloud ├

Every finding cites its rule.

  • Duplicates, unbundling, upcoding, surprise-billing protections, appealable denials.
  • Grounded in Google Search; sources and search suggestions shown.
  • No citation, no claim: it becomes a question to ask the billing office.
07
┤ Write · on device ├

Placeholders in the cloud. Your name, only here.

  • The cloud drafts with tokens: ⟦PATIENT_NAME⟧
  • The vault fills them in locally. Print, copy, done.
  • Every crossing is in the boundary panel, exportable as JSON.
